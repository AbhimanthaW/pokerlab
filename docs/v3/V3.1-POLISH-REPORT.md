# PokerLab V3.1 polish report

22 October 2026. Implementation and automated verification delivered; visual/browser acceptance remains open. No deployment or V4 work.

## Initial issues and changes

| Before | V3.1 implementation |
| --- | --- |
| Large bottom-right panel with permanent amount editor | Compact contextual action bar; desktop horizontal actions; mobile two-column actions |
| Raise editor always occupies space | Bet/Raise opens integer total input, slider, min/max, Confirm and Cancel; Escape cancels and returns keyboard focus |
| Repeated board and private card HUD | Physical cards are the default; readable cards and all opponent stacks are available through Table details |
| Outer opponents near viewport boundaries | Seated camera backs away from 4.85 to 5.65, rises from 1.6 to 1.75, retains 53-degree field of view; labels move inward |
| Large empty space during NPC turns | Action bar remains absent outside human turns; compact existing actor status retained |

All legal buttons still derive from the existing engine descriptor, including short all-in actions. Raise amounts remain final total commitments. A synchronous submission guard and existing revision/session reducer guards prevent duplicate commands. The existing 2D presentation retains its previous amount editor. No engine, NPC, save-schema, assets, materials, lighting, audio or dependency changes.

Community street remains in the status HUD. Revealed board and human private cards retain screen-reader text. Table details is a keyboard-operable disclosure with readable cards, opponent names/stacks and Folded/All-in/Eliminated states, useful on narrow viewports or after looking away. The numerical human stack remains visible. Settings, mute, fullscreen, camera reset and bounded camera gestures remain available. Mobile side-pot positioning and short landscape editor scrolling are accounted for in CSS.

## Animation, audio and performance review

Existing card identity/resource tests cover immutable snapshots without repeat flips, legitimate reveal only, restoration and reduced-motion convergence. Existing presentation tests cover hidden-information isolation, stale revision rejection and bounded event queues. NPC/card/chip animations remain presentation-only. Existing AudioManager tests cover explicit unlock, independent levels, visibility pause, disposal and interrupted asynchronous unlock. No new audio/animation defect was established in this pass, so these systems were preserved.

Source audit: chip meshes remain instanced and capped at 28 instances per stack; card textures retain identity across cloned snapshots and dispose on replacement; effects remain capped at 64 events. There is one R3F frame loop, disabled when inactive and demand-driven under reduced motion. Resize, visibility and context-loss listeners have cleanup. Low/Medium/High/Auto settings, shadows and DPR caps of 1/1.4/1.8 remain unchanged. Removed the verified redundant per-frame projection-matrix calculation. No speculative material/geometry rewrite.

Actual FPS, draw calls, GPU memory and audio listening could not be measured because browser launch failed. No measured speedup is claimed. The roughly 941 kB lazy Three.js scene chunk still produces Vite's size warning; the existing local WAV remains roughly 6.44 MB.

## Automated verification

Baseline independently rerun: 189 tests passed, one optional exhaustive census skipped. Final results are recorded in STATUS.md and TESTING.md. The unchanged suite includes V1 learning regressions, V2 rules/NPC/persistence tests and 5,000 seeded hands with invariants after every transition. SHA-256 comparison of all 25 V1/V2 domain files against the retained V3 baseline found no differences.

Added seven tests: three compact control tests, one immersive cancel/commit integration test and three desktop projection cases. These establish behavior and geometric anchor margins; they do not establish visual quality or actual DOM layout in a browser.
